## Log data, metadata, syslog (Source: Pt6 p.52)

- **Log data** — OS and applications software can be configured to log events automatically.
  - Provides valuable troubleshooting information.
  - Security logs provide an audit trail of actions performed on the system as well as warning of suspicious activity.
  - It is important that log configuration and files be made tamperproof.
- **Metadata** — information stored or recorded as a property of an object, state of a system, or transaction.
  - File: date/time and security attributes.
  - Web: request and response headers.
  - Email: Internet header listing message transfer agents ("(SPAM)" is printed after "message transfer agents" on the slide; recorded as shown).
- **Syslog** — an application protocol and event-logging format enabling different appliances and software applications to transmit logs or event records to a central server.
  - Works over **UDP port 514**.
  - The **PRI (priority)** code is calculated from the facility and a severity level.
  - The **HEADER** contains a timestamp, host name, app name, process ID, and message ID fields.
  - The **MSG (message)** contains a tag showing the source process plus content.

(Source: Pt6 p.52)

## Application, endpoint, and OS logs (Source: Pt6 p.53)

- **Application logs** — logs that are managed by an application rather than the OS. The application may use Event Viewer or syslog to write event data using a standard format, or it might write log files to its own application directories in whatever format the developer has selected.
- **Endpoint logs** — a target for security-related events generated by host-based malware and intrusion detection agents. Security software running on hosts; summarize volume of detection incidents to indicate threat levels; incident attribution and threat intelligence.
- **Host operating system (OS) logs:**
  - **Windows** — Windows Event Viewer: a Windows console related to viewing and exporting events in the Windows logging file format; Application, Security, and System [logs].
  - **Linux** — syslog versus journald [slide spelling "Journald"]; common log files.
  - **macOS** — Unified Logs.

## Network data sources (Source: Pt6 p.54)

- **Network logs** — a target for system and access events generated by a network appliance, such as a switch, wireless access point, or router. Traffic and access data from network appliances; generated by appliances such as routers, firewalls, switches, and access points.
- **Firewall logs** — a target for event data related to access rules that have been configured for logging. Correlate to malicious activity on hosts. A firewall audit event will record a date/timestamp, the interface on which the rule was triggered, whether the rule matched incoming/ingress or outgoing/egress traffic, and whether the packet was accepted or dropped.
- **IPS/IDS logs** — an event when a traffic pattern is matched to a rule. Summarize volume of detection incidents to indicate threat levels; attribution and threat intelligence.

(Source: Pt6 p.54)

## Data sources: scans, reports, dashboards, packet captures (Source: Pt6 p.55)

- **Vulnerability scans** — can be configured to log each vulnerability detected to a SIEM; can include missing patches and noncompliance with a baseline security configuration.
- **Automated reports** — alerts and alarms; status reports for response team, business managers, business owners, and compliance.
- **Dashboard** — a console presenting selected information in an easily digestible format, such as a visualization.
  - **Analyst dashboard** — console of alerts that require prioritization and investigation.
  - **Manager dashboard** — overall status indicators.
- **Packet captures** — provide a complete, packet-level history of all network activity. Reconstruct events, analyze the data, and drill down to the actual network packets to pinpoint precisely what took place. Helps analyze networks, identify network performance issues and manage network traffic.

(Source: Pt6 p.55)
